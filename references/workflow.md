# 统一执行流程

版本：2026-10-14.2。本文件是执行顺序的唯一来源；按需读取下列引用，不重复全文加载已读规则。

1. **开始与读取**：记录本次起点；用户要求统计时按 [计时](timing.md) 分阶段记录。查看实际图片并提取文案，按 [比例规则](canvas-ratio.md) 提取每个交付物的目标画幅及来源，识别活动、受众、包含内容、实际主体与关键事实。先执行 [文化检查](cultural-review.md) 的输入隔离。文件未变且用户允许时复用本任务缓存；用户要求从头开始则不读旧分析或旧选择。
2. **素材理解确认**：一张问题卡明确展示并确认活动类型、受众类型、包含内容（对应案例库标签），以及以上理解、保留/排除项及事实缺口，并询问是否联网查找设计素材。相同版本已确认或用户明确免确认则跳过；只有明确授权才编写虚构信息。完整交互只读 [提问规范](question-format.md)。
3. **一次研究**：按 [案例检索](case-retrieval.md) 依据需求卡已批准的三项标签运行一次本地检索，同时取得风格、构图与主体组织证据。获准联网后与案例检索并行；按 [素材与配色](material-planning.md) 搜索并实际查看图像、纹理、图形元素及视觉参考，文化和使用条件核查仅作辅助。记录来源→可用特征→画面应用，设计选择前简述采用方案；未找到合适素材则说明，不强加元素。资料充分不追加搜索。
4. **准备并同轮选择**：推荐遵循 [固定判断顺序](recommendation-order.md)：用户要求 → 素材与主题适配 → 案例匹配 → 风格表现能力。候选阶段只读 assets/catalogs/styles.json 的摘要，不读全部配方。依据原图主色关系提出配色；按主体与文案准备构图，优先展示 assets/layout-previews 中的内置灰度图，按 index.json 选择对应图片或使用 all-layouts.png 总览，不重写绘图代码。位置与比例可调整，不是固定模板。正文先实际展示内置灰度排版图，再一次问题卡调用分别问风格、配色、构图；配色使用简短文字选项，不生成配色色块图。收齐答案再继续；已指定项跳过。等待用户回答，不设置定时提醒。
5. **一次生成每版**：通过 [本地映射](local-style-skills.md) 只读选中配方和 [风格转译](style-translation.md) 对应部分，简约风内部明确保留、归并、重画和避免项；其余风格直接依据自身配方，不额外叠加风格限制。按 [整图生成](complete-poster.md) 编译短设计说明并检查原图角色、具体重画方法与冲突，将选中排版转成标题、信息区与素材的具体关系（不能只写构图名），把选用的网络素材转成具体应用动作，再压缩提示词，核对全部文案、文化限制、原图主色及面积关系、风格和构图，不再普通确认。画幅按 [比例规则](canvas-ratio.md) 读取与确认，宽:高及方向无冲突后才生成；每个请求的语言版本一次完整生图，独立版本可并行。文字直接生成，不手工合成，不先做无字底图，不自动修正重生成。
6. **集中验收交付**：按 [集中验收](final-review.md) 执行：一次程序调用批量处理所有版本的实际尺寸、必要的安全画布修整、比例复验及短报告；每张最终图集中查看一次，同时核对全部批准文案、图文关系、主体与文化问题及实际网络素材应用。不重复读取已加载的规则，不拆成多轮逐项检查，不另写长篇设计或检查报告。仅发现具体疑点、内容变更或工具失败时追加针对性检查。保留原始输出，不自动再次生图；比例、尺寸及内容完整性通过才交付最终PNG，必要不足如实说明。统计请求附实测用时，不虚构Token。

## 缓存和读取范围

提取文案、图片分析、文化记录、批准事实、案例结论与推荐依据写本次可写输出目录。记录源文件 SHA-256、相关规则版本和影响匹配的标签；文件、规则或定义变化只重做受影响部分。缓存不打入 skill 包、不跨用户复用。路径相同不是缓存有效依据。

只保留简短任务摘要与批准文案；最终提示词不放整库、全部配方、未选方案或历史网页。研究先摘要，通常只打开1–3个可靠相关来源；必要核实不受该数量限制。选择完成后必读 layout-catalog.md 中选定类别及编译与检查要求，适用于所有风格，其余溯源/安装说明不作为每次生成必读。

比例验收按 canvas-ratio.md：默认相对偏差不超过5%且方向正确即通过，不因像素取整误差重生成或补问。仅明显超差或方向错误时每版最多自动重生成一次；用户明确要求精确比例时使用0%容差。报告实际尺寸，不把近似称为精确，不拉伸、裁切或补边凑比例。
