# 提问统一使用按钮

## 真实可点击选项

所有提问使用宿主的交互选择组件。当前 Codex 环境优先调用 `request_user_input_async`，每个问题必须提供非空 `options`，保留组件自带的自由填写入口。不仅在普通聊天中列 A/B/C 或 1/2/3，也不用 Markdown 链接假装按钮。用户主动提供的文字、方案编号或明确委托同样有效；已有答案直接记录，不强求重新点击。

先展示已检查的方案、理由、参考图或预览，再通过工具提问。按钮写具体名称与关键差异；排版带模板 ID，颜色使用实际方案名。有推荐时在对应按钮标“（推荐）”并说明依据；预选不等于提交。单次通常一个问题，最多合并 2–3 个互不依赖的问题。风格、配色、排版按素材和前一步选择依次推导，不提前让用户选择未经筛选的方案。

## 门禁选项示例

按本次素材改写以下示例；既有筛选、确认与文化审核要求不变。

| 提问 | 按钮选项 | 处理 |
| --- | --- | --- |
| 画布比例确需确认 | 2:3／3:4／4:5 | 记录具体比例；没有提问时原默认比例仍有效 |
| 多图组织 | 合成一张海报／分别制作海报／部分图片仅作参考 | 仅作参考时还须明确各图角色 |
| 主体方式 | 抠出主体做移动图层／整图作为移动底图 | 抠图后续仍需确认具体名单 |
| 抠图名单 | 确认以上主体／增加主体／减少或调整 | 增减需先获得具体变化，再确认更新后的名单 |
| 联网补充 | 仅使用现有素材／搜索后由我确认／授权你选择并加入 | 对应 `none`、`suggest`、`use`，范围与元素审核照常执行 |
| 风格 | 2–3 个实际适用的当前风格名 | 先说明本次素材上的可见差异 |
| 配色 | 2–3 个实际方案名，如“海蓝＋暖白” | 先展示底色、主色、强调色、文字色与 HEX |
| 初始排版 | 3–4 个通过筛选的模板 ID＋结构名 | 每个按钮对应已展示的实际文案预览，不加入遮挡方案 |
| 文案确有缺口 | 我补充真实信息／先保留空位做草稿 | 不虚构事实；第二项只适用于可留空的草稿 |
| 文化语境有具体疑点 | 提供出处与说明／替换该元素／排除该元素 | 依据实际发现改写，获得所需事实后再审核 |

不必另加“其他”或“自定义”按钮，原生工具已有自由输入入口；没有该入口的宿主可提供“自定义需求”按钮并收集文本。点击“增加”“调整”“提供说明”仍未给出具体内容时不能视为完成确认；后续提问也提供可行按钮与自由填写入口。不要重新加入是否生成艺术标题的门禁。

## 当前工具参数示例

已展示两种实际适用风格的差异后，可调用：

```json
{
  "questions": [{
    "title": "这张海报采用哪种风格？",
    "options": ["轻插画：柔和几何与渐变（推荐）", "套色油印：网点与两墨印刷"]
  }]
}
```

实际选项随素材变化，不能机械套用这个例子。工具返回后问题可能仍等待回答；继续独立的文案核对、图片检查和方案准备，必需选择没有答复时不执行依赖它的操作。把实际选项和真实回复记录在现有生成笔记、工程字段中，不把默认项记成用户回答。

## 跨宿主兼容

有等效原生交互选择工具时，使用其真实按钮或选项组件，并遵循工具约束；不在不支持的模式调用工具。没有原生提问工具时，使用可显示或打开的 HTML 选择面板，含真实按钮或单选项、自定义输入框和明确的“提交选择”按钮。仅实际提交后才确认；生成、打开或预选面板不算回答。通过宿主可观察的提交结果或用户返回的选择记录继续。

若宿主也无法展示该面板，说明按钮界面能力缺失并保留必需选择待回答，不能声称纯文字列表满足本规则。现有 HTML 编辑器中用户明确点击风格、排版或配色采用按钮，可作为相应选择，仍遵守原 HumanGate。
