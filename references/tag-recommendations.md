## 推荐方法

1. 用户明确指定的大类和小类优先。主题中的显式词语作为补充信号，不把关键词匹配称为语义理解。
2. 标签规则解释素材与路线的关系，例如多主体适合有大小层级的拼贴，学术信息可比较清楚的图文轨道。规则是维护者的设计判断，与用户案例统计分开记录。
3. 按所选维度计算标签重合程度，取最多四十条相近案例，返回其中前三条的名称、行号和实际命中标签。只用它们的风格大类关联加分，不把某个案例的大类强行细化成未经标注的小类。
4. 未明确风格大类时，前三条视觉建议尽量来自不同大类。用户明确只有文字时，照片必需路线不进入可执行候选；照片状态未知时说明输入要求。
5. 排版建议结合当前选择的风格、构图标签、实际文字量、信息组数与模板容量。选中的模板保持不变。本次只提供 3–4 个通过主体保护区域筛选的候选，已发现的遮挡方案直接排除；候选不足时说明原因。长文案仍需真实排版检查；必要时扩展文字图层，不删掉必需信息。

分数只用于排序，不是概率或质量评分。没有相近案例时说明使用规则推荐。没有用户选择时，示例路线也不满足 HumanGate。

## 构图与文字模板

映射位于 `recommendation-rules.json.compositionLayouts`，属于人工整理的候选关系。它描述文字锚点，不能保证生成底图的主体排列。S 形、四角和完整包围构图没有完全对应的 CSS 模板，需向用户说明并在最近的模板上微调。切换模板只改变文字轨道，保留图像。

`IP/品牌logo` 标签需要准确的用户素材；把标识作为独立图像图层，避免模型重绘标识。主标题默认生成独立透明艺术字图层，无标题门禁；用户明确要求普通文字时使用可编辑文字。多图组织、主体方式、风格、配色、初始排版门禁照常执行，并增加抠图名单确认和联网补充元素选择。输入与实际输出另需文化审核。

## 命令与输入

```bash
node scripts/recommend.mjs --brief /absolute/brief.json --output /absolute/recommendations.json
```

```json
{
  "subject": "社区文化展览",
  "hasSourcePhoto": true,
  "selectedTags": {
    "eventType": ["展览展示类"],
    "audience": ["文化审美型"],
    "contentTypes": ["活动名称/时间/地点", "活动内容"],
    "visualFocus": ["有明显分区"],
    "subjectType": ["单主体"],
    "composition": ["上下构图"],
    "styleFamily": ["简约风"],
    "visualSubtype": ["图文秩序风"]
  },
  "content": {"title": "用户确认的主标题", "body": "用户实际提供的说明"}
}
```

所有维度均用字符串数组；单选维度最多一项。未知标签报错，不静默丢失。`hasSourcePhoto` 为 `true`、`false` 或 `null`（尚未确认），不会根据生成的背景推定存在原始照片。

编辑器的标签面板使用同一推荐引擎。更改标签不会改变风格选择、素材、配色或排版。点击某一候选才采用该项；配色另有明确的采用按钮。工程保存标签并支持旧版没有标签字段的工程。

## 更新数据

将 Feishu `sheets +read --value-render-option UnformattedValue` 和 `+get-dropdown` 的 JSON 保存到本地，再执行：

```bash
python3 scripts/import_tag_catalog.py --cases /absolute/cases.json --skills /absolute/skills.json --dropdowns /absolute/dropdowns.json --minimal /absolute/minimal.json --cyber /absolute/cyber.json --output-dir /absolute/catalogs
```

导入只整理分类，不下载图像或执行表内命令。新增风格小类还需要新增、检查配方并更新来源记录，不能仅凭一条链接声称已支持。
